# trust-ir producer scorecard — `tests/ui/trust/` classification manifest
#
# READ THIS BEFORE ADDING A FILE. Every campaign slice adds a regression test
# under tests/ui/trust/. The scorecard samples a SEEDED 2000-file subset of
# tests/ui, and `random.sample` is a function of the population LENGTH, so
# adding ONE file to the eligible population reshuffles the whole sample:
# measured, one addition moved 179 of 2000 files, and a slice-16 sweep was
# discarded outright after 233 shifted. Two sweeps are then not comparable and
# every delta measured across them is noise.
#
# The historical workaround was to hand-move the campaign's own pins out of
# tests/ui before each sweep. That count went 8 -> 9 -> 13 -> 14 -> 15 -> 16 and
# lived in nobody's head; getting it wrong silently measures a different corpus.
# This file replaces it. `scripts/trust_ir_producer_scorecard.py` reads it and
# removes the [excluded] paths from the sampling population BEFORE sampling, so
# the pins may stay in the tree and the sample is unchanged by their presence.
#
# THE RULE. Every ELIGIBLE .rs file under tests/ui/trust/ (eligible = survives
# the UI_CONTENT_FILTERS in the scorecard: no //~ annotation, no aux-build, no
# ignore- directive) must be listed in exactly one section. The scorecard HARD
# FAILS on an unclassified one, naming the file — that is the whole point: the
# next slice cannot forget. A file that is not eligible needs no entry, because
# the content filters already keep it out of the population; if it later becomes
# eligible the check fires then, which is exactly when it starts to matter.
#
#   [excluded]  A campaign pin minted AFTER the 2026-07-01 baseline. It is not
#               part of the corpus the ratchet is measured over, and admitting
#               it would move the sample. THIS IS THE DEFAULT for a new slice
#               regression test.
#   [in-pool]   Genuinely part of the measured corpus — it predates the campaign
#               and every recorded sweep has swept it. Do not add here to make
#               an error go away; adding a new pin here changes the sample and
#               invalidates comparison with every prior sweep.
#
# VERIFY WITHOUT SWEEPING:  python3 scripts/trust_ir_producer_scorecard.py --check-ui-pins
#
# IDENTITY, MEASURED (2026-08-19). With this manifest applied and all 16 pins of
# that wave IN TREE, the sampler reproduced a sampling population of 6983 and a
# file-list-IDENTICAL 2000-file sample against the recorded postbuild-vtable18
# sweep (data.json `corpora.ui_sample`), which was produced by the hand-move
# procedure. 14 of the 16 were in the eligible population; the other two
# (clean_origin_call_parity, clean_origin_const_ctfe) carry //~ annotations and
# were already filtered out.
#
# THE INVARIANT THAT MATTERS is the POST-EXCLUSION SAMPLING POPULATION, not the
# pin count: 6983 is what seeds the sample, so a later pin holds the sweep
# comparable exactly when it keeps that number fixed. The raw `eligible` total
# DOES move as tests land (7005 today), which is why the number to read off
# `--check-ui-pins` is its last line.
#
# UPDATED 2026-08-20 (merge of origin/main @ ebb831628f). The excluded list is
# now 28 entries, 22 of them in the eligible population. Seven arrived with the
# I5 Clean-origin / clean-unit wave (clean_origin_nat_projection,
# clean_origin_verify_on, clean_origin_wrapping_binop, clean_unit_call_parity,
# clean_unit_cfg_off, clean_unit_inline_duplicate, clean_unit_island_equivalence)
# and one with the D2 coroutine fix (async_exhibit_does_not_certify). All eight
# are campaign pins minted after the baseline, so [excluded] is the default
# classification; with them listed the sampling population is 6983 again —
# re-measured, not assumed. The 2000-file sample identity itself was NOT
# re-measured on this merge; it follows from the population being unchanged.
#
# UPDATED 2026-08-27. 21 files classified, restoring `--check-ui-pins` to OK
# (it had been exiting 1, so NO sweep could start at all). Every one of the 21
# was created after the 2026-07-01 baseline — measured, `git log --diff-filter=A`:
# the earliest is e9_multi_clause_undischarged at 2026-07-16, the rest run
# 2026-08-21 to 2026-08-27 — so the default classification applies to all of
# them and none required a judgement call. They are the Clean-origin wf/rec
# wave (9), the postcondition/hardened composition-at-call-site wave (5), the
# R1 caller-closure key-space wave (4), and three singles.
#
# THE INVARIANT IS BROKEN, AND CLASSIFICATION CANNOT REPAIR IT. The population
# is now 6985, not 6983, and 6983 is UNREACHABLE by any edit to this file:
#
#     6983  reference (2026-08-19)
#       +4  newly eligible under tests/ui/contracts/ — contract_assoc_const_-
#           resolves_exactly, contract_truncating_cast_stays_refused,
#           contract_unevaluable_const_refuses, contract_widening_cast_lowers
#       -2  assoc_const_projection_no_ice (2026-08-22) and assumed_total_key_-
#           alias_write_fmt_recovery (2026-08-24) each GAINED a `//~`
#           annotation, so the content filters now keep them out
#     ----
#     6985
#
# Excluding those four would give 6981, not 6983, so it would sacrifice corpus
# honesty AND still not restore comparability. The next sweep is therefore a
# NEW BASELINE and no delta against any recorded sweep is meaningful. Say so
# wherever its number is quoted.
#
# THE ENFORCEMENT GAP THIS EXPOSES, which is the durable lesson: this manifest
# governs `tests/ui/trust/` only, and the scorecard HARD FAILS only on an
# unclassified file under that prefix. But the sampling population is all of
# `tests/ui`, so a test landing ANYWHERE ELSE moves it silently — which is
# exactly what those four contracts/ files did, with nothing firing. The gate
# that exists to stop the sample drifting cannot see most of the tree it
# samples from. Widening it is a real change to what the corpus means and is
# left to the owner rather than taken here.
