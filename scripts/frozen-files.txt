# A citation written `<commit>:<path>` names a record that git keeps at that
# commit (the 2026-11-09 document cleanup deleted it from the tree); read it with
# `git show <commit>:<path>`.
#
# WHY THIS FILE EXISTS
# --------------------
# The differential is the ORACLE: rustc's own freshly-built MIR is what the
# AI-generated compiler components are checked against. Weakening it manufactures
# agreement instead of earning it, so the files that implement it are FROZEN.
#
# Until 2026-08-20 that freeze was enforced by lanes REMEMBERING it. Measured on
# that day, three commits had moved two of the four frozen files and nobody
# noticed until an audit went looking:
#
#   e73d7d0553  crate_module.rs (+280/-13)  and  differential.rs
#   5b38ded9d9  crate_module.rs (+23/-0, doc comment only)
#   65f2577dca  differential.rs (+949/-12)
#
# All three were adjudicated LEGITIMATE on their merits
# (reports/freeze-adjudication-2026-08-20.md) — which is exactly why a memory-
# enforced freeze is the wrong instrument. A rule that only fires when someone
# remembers it cannot distinguish the three good commits from the bad one it
# exists to catch, because it does not fire at all.
#
# COLUMNS
# -------
#   path | pinned-blob-sha1 | rule | one-line reason the file is frozen
#
# `rule` is NOT machine-checkable and the gate does not try. It records what a
# waiver for this file must ARGUE:
#
#   BYTE-IDENTICAL          no change of any kind, comments included
#   SAMPLE-MORE-OR-REFUSE-MORE
#                           a change may widen what is compared or add a
#                           refusal; it may NEVER widen what is ACCEPTED
#
# The gate checks BLOB IDENTITY only, for both HEAD and the working tree. That
# is deliberate: blob identity is the one property a script can decide without
# judgement, and every judgement call is therefore pushed into a WRITTEN waiver
# with a name on it (scripts/frozen-waivers.txt) instead of into a heuristic
# nobody audits.
#
# Since 2026-09-24 a waiver may also CITE the test that fails if its argument is
# false (`ENFORCED-BY:`, resolved by the gate; see scripts/frozen-waivers.txt),
# and flip_registry.rs has a REFINEMENT HARNESS that compiles THE PIN BELOW
# beside the working tree and checks `current_accepts(x) => pinned_accepts(x)`
# (crates/trust-thir-lower/src/flip_registry_refinement_tests.rs, fed by the
# crate's build.rs). Moving that pin re-baselines the harness; if the pinned
# signature changed, its pinned-side wrapper is updated in the ratifying commit.
# Ratifying at the WORKING TREE's blob needs no OTHER harness edit: the "refuses
# more" witness is conditional on the pin differing from the tree (the build
# script computes `PIN_IS_CURRENT` from the two sections it compiles), and at
# pinned == current the harness demands the two gates agree instead. The NEXT
# movement names its lane and witness in the harness's `waived_delta` block.
# (Corrected 2026-09-28: this paragraph used to say ratifying at the working
# tree's blob "needs no harness edit" outright. The 2026-09-28 ratification,
# 771cd9ec -> 2a7207af, crossed the gate's signature change and had to rewrite
# the pinned wrapper; so does any ratification across a signature the wrapper
# spells.)
#
# Since 2026-09-27 mir_differential.rs has a refinement harness too, fed by the
# same build.rs table (crates/trust-thir-lower/src/mir_differential_refinement_tests.rs).
# It compiles THE PIN BELOW beside the working tree and checks, over a corpus of
# VerifiableBody pairs, that the TyCtxt-free verdict core (canonicalize,
# canon_markers, the refs guard composed as the pair verdict; canonical_cfg_roles
# per side, since step 2.5's composition is not in this file) admits nothing the
# pin refused — and, for the current waiver, is IDENTICAL — plus a CENSUS: the
# ordered production-token diff pin -> tree must equal the harness's
# `waived_delta::TEXT_DELTA` exactly, so a movement in a TyCtxt channel the
# behavioural half cannot see still fails until a waiver names it. Once named it
# passes: nothing here runs TyCtxt code, so whether a named TyCtxt-side movement
# is harmless stays the waiver's argument, declared in its PROSE-RESIDUAL clause
# and counted by the gate (scripts/frozen-waivers.txt). Ratifying at
# the working tree's blob leaves the census delta empty, and needs no harness
# edit only while one `observe_wrapper!` serves both sides: a movement that
# changes a signature the wrapper spells gives the pinned side its own wrapper,
# and the ratification after it rewrites that one (as flip_registry.rs's did).
# The NEXT movement writes its own TEXT_DELTA, and clears VERDICT_CORE_IDENTICAL
# if it refuses more.
#
# TO CHANGE A FROZEN FILE
# -----------------------
#   1. Make the change and state, in the commit message, which half of the rule
#      it satisfies and how that was MEASURED (not argued).
#   2. Add a waiver row to scripts/frozen-waivers.txt naming the file and the
#      exact NEW blob, with its `PIN-DELTA: +A/-D` against THE PIN BELOW (not
#      against the previous waiver; the gate measures it).
#   3. Ratify by moving the pin here and DELETING the waiver, once a review of
#      the file's WHOLE movement from the pin finds no hunk that admits more;
#      where the claim fails, restore the refusal (with a RED/GREEN test) and
#      pin the corrected blob. The author of the movement does not certify it
#      alone. The gate fails on a waiver that is no longer needed, so a waiver
#      cannot outlive the change it documents.
#
