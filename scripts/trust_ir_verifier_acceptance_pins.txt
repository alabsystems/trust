# trust-ir VERIFIER acceptance pins — the verdicts the trust-ir verification path must reproduce.
#
# Owner direction 2026-09-29 (accounting invariant, item 2): the regression tests
# of the 2026-09-28/29 residency, identity, requires and std-member work are
# registered here as acceptance pins for the trust-ir path. Under R-1/R-2
# (docs/plans/2026-09-29-trust-ir-sole-compile-path.md) verification moves onto
# trust-ir and the MIR-derived lanes become test oracles. Before a MIR-derived
# verification lane is retired, the trust-ir path must give every fixture below
# the verdict its directives and `//~` annotations demand today. A refusal pin
# that turns into an accept re-opens a measured false PROVED; a `keeps_*` control
# that turns into a refusal is a capability loss (docs/DECISION_QUEUE.md first).
#
# Format: <fixture> <class> <invariant-tag>
#   class  accept | refuse | mixed:<passing revisions>/<revisions>, DERIVED from
#          the fixture's pass-mode directives by the checker; a mismatch fails
#          --check, so moving a pin's verdict takes an edit here, in the open.
#   tag    which invariant the fixture pins:
#          r2-residency    an item's identity is its artifact residency in this
#                          compiler's sysroot, never a lang/diagnostic item or a
#                          crate name a dependency can declare
#          requires-edge   a `requires` is charged at every edge that can call
#                          the function (fn pointers, items handed to std, trait
#                          impls), or the edge is refused
#          std-member      a bundled std member's gap is a runtime_checked ROW,
#                          only for std's own check, never registry authority
#          skip-ledger     a skip is an honest, recorded, fail-closed row
#          e6-admission    a body the E6 reader admits for a Clean-certified
#                          contract keeps that certificate, and every shape it
#                          refuses (impure arms, unsupported widths, guards,
#                          loops, ref-self views) stays refused; the trust-ir
#                          path must reproduce both directions
#
# CHECK (no build):  python3 scripts/trust_ir_verifier_acceptance_pins.py --check
# DERIVE A CLASS:    python3 scripts/trust_ir_verifier_acceptance_pins.py --derive
#
# Adding a pin: any tests/ui/trust fixture whose verdict closes a hole or keeps a
# capability belongs here. Run --derive for its class. Removing a pin needs the
# same justification as deleting the fixture.
