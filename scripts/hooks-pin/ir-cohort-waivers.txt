# IR-cohort waivers, read by scripts/check_ir_cohort.py.
#
# A row here means: "this part of the cohort is knowingly on a DIFFERENT trust-ir
# semantics from the ratified one, someone owns moving it, and the pushing lane
# is not the cause." The gate steps over the listed schema and BLOCKS on every
# other divergence. It is per-schema on purpose --- a whole-gate quarantine
# would waive the next divergence too, which is the only one the gate exists to
# catch.
#
# Format (`|`-separated, one row per line):
#     <dependency> | <schema digest> | <expires YYYY-MM-DD> | <owner> | <reason>
#
# Rules the gate enforces mechanically, so a row cannot rot:
#   * past `expires`, the row stops applying and the divergence blocks again;
#   * once the divergence is GONE, the row FAILS the gate until it is deleted.
#
# NOT WAIVABLE, by any row: a revision that does not resolve, and a revision not
# contained in the dependency's origin/main. The second is the fork case --- two
# consumers on divergent branches can disagree arbitrarily while both look
# current, and no expiry date makes that safe to ship.
#
# The ratified schema is the one at the superproject's recorded gitlink for that
# dependency. Burning a row down means moving another lane's pin, which is a
# COORDINATED act: open it with the owning lane, do not push the bump unilaterally.
#
