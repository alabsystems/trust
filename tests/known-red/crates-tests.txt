# push-tier `scoped.crates-tests` lane). One row per failing test, keyed
# `<test binary>::<test path>` exactly as the lane prints it.
#
# This is a RATCHET, not a mask: a failure NOT listed here fails the lane, and a
# listed test that runs and PASSES also fails the lane until its row is deleted
# (rows tagged [flaky] are exempt from that half: load-sensitive tests that may
# pass or fail). Every row says why it is red and who owns the fix; delete the
# row in the commit that fixes the test.
#
# [flaky] has a second, narrower use (added 2026-09-29): a test that is red where
# it runs but returns early and passes VACUOUSLY when a prerequisite is absent
# (a built binary, say). Whether it passes then depends on the checkout, not on
# the code. Such a row names its prerequisite. Because [flaky] exempts it from
# the ratchet, a fix will never fail the lane to prompt the row's deletion:
# delete it by hand in the fixing commit.
#
