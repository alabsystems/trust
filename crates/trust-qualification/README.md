# Native paired qualification inputs

The first stage of `targo trust gate qualify-pair` owns complete immutable input
binding. `pair::inspect` consumes both toolchain seals, the exact candidate
receipt, clean locked AY/trust-vc source closures, proof fixtures, the explicit
trust-spec scaffold and ambient Cargo configuration (including absence).
Optional dependency roots bind all their bytes, including enclosing workspace
and ignored source files. They do not claim metadata resolution has completed.

`InspectedPair` owns the request and snapshot and rebinds them before another
stage may consume it. It has no execute, proof, candidate acceptance or publish
methods. Its report names the remaining receipt/probe/admission/run/census/
comparison/landing stages. A copied receipt is only bound bytes at this stage;
its schema, build status and writer have not been authenticated.

`qualify-pair receipts` consumes that live `InspectedPair` through
`check_receipts`. The native stage reader validates vocabulary, every listed
executable hash and compiler-commit statement. The candidate must additionally
state a clean, stable completed stage-two-or-later Trust-from-Trust source
closure with the exact required shipped tools. Its receipt hash must equal the
original inspected bytes; the complete original inputs are rebound before and
after these checks. A missing control receipt is disclosed; a present malformed
receipt refuses. The returned `ReceiptCheckedPair` is not deserializable and
retains the original owner for subsequent drift checks.

`receipts-checked` is consistency of declared provenance and observed bytes.
It does not authenticate a build or a writer. Actual compiler identity probes,
locked dependency resolution, admitted execution, complete source-bound census,
measurement, comparison and landing remain pending in its report.

The same live owner also provides compare_ay_censuses for retained AY v3 census
files. It rebinds the complete original pair before and after every outcome,
obtains the exact crates/ay-proof-common Git tree from that source, and checks
both reported source identities, a positive complete ledger, truncation
evidence, strict/advisory agreement and class/rollup consistency. Files are
bounded, exact regular files; duplicate JSON keys, wrong numeric types,
unknown classes and changed backing refuse.

Its native identity accounting distinguishes a named solver discharge from
removed obligations, newly emitted rows and structural verdicts. Removed or
downgraded proved identities, falling solver/kernel floors, new timeouts and
unexplained failed/unknown growth remain regressions. Newly emitted skipped
rows explain only their existing inclusion in the unknown rollup.

This saved-data consumer does not advance the execution stages or authenticate
the census producer. The future admitted workload owner must bind its exact
bytes to actual attempts and exits before consuming it for a candidate decision.
There is no new command or wrapper, and the script's active callers remain
until its workload producer, measurements and final decision also migrate.

The complete seal reader is byte-compatible with `seal-content-v1`: every file,
directory and link contributes path bytes, kind, normalized mode and content,
with only promotion's four root record exclusions. Source/dependency digests
have their own versioned scopes. Tracked source bytes must match actual Git
blob IDs; source links must reach tracked regular files in the same closure;
hidden index flags, nonempty Cargo markers, path substitution and unsupported
file types refuse. Git probes come from the host's existing controlled system
Git implementation, never PATH discovery.

Every source/dependency link also binds its selected canonical relative file;
an ignored intermediate hop cannot silently select another already-bound file.
Pair inspection preserves the compatible seal digest and separately binds
resolved seal links and excluded promotion records. The seal digest alone does
not establish that a covered link still selects the same library.

These are local diagnostic drift checks, not an OS snapshot or proof against
edits restored between observations. Hold sole ownership of all source and
artifact inputs. No old paired runner, receipt validator or AY census producer
is retired by these stages. The full paired runner must acquire those
responsibilities before their supporting policy tools can be deleted.

The explicit `probes` stage consumes `ReceiptCheckedPair` and one matched native
Targo metadata service under the host's original retained fixed-one CPU/GNU/
memory and genuine service SDK keeper. Both frozen target SDKs are independent
of that service SDK. The service admits only the exact version/sysroot/Targo
version argv, a clean semantic environment and bounded native image/runtime
inputs. It retains actual preparation/start/outcome/stream facts; old hosts and
unsupported ancestor custody refuse, with no pool or legacy fallback.

The original complete snapshot is rebound before and after every outcome,
including failed transport. Partial failed native observations, original input
identities and available start facts remain in the refusal report. Successful
label/sysroot consistency is diagnostic evidence, with workload resolution,
execution, complete census, measurement and comparison still pending. It
authenticates no source, build, proof or release. Frontend Git preparation is
outside this metadata-only admission. [MIGRATION.md](MIGRATION.md) maps the exact
native boundaries, remaining responsibilities and helper deletion conditions.

Run this library's focused source checks with genuine Targo:

```sh
build-slot --cpus 7 -- targo --unverified test --manifest-path crates/trust-qualification/Cargo.toml --lib
```

The live compiler-probe owner now transitions through
`ProbeAttempt::resolve_dependencies` into complete locked/offline dependency
comparison. Failed probes retain their original report and refuse before a
resolver is called. Four requests bind each exact sealed Targo to each frozen
AY/trust-vc source, the explicit Cargo home and the fixed
`metadata --locked --offline --format-version 1` argv.

The `dependencies::DependencyResolver` consumer keeps every attempted, failed
and not-attempted record, exact bounded stdout/stderr and native producer
observations. It compares all package objects, the complete resolve object and
the complete workspace-member inventory. Duplicate JSON keys, lossy number
comparison, missing graph members, AY substitution and unfrozen path packages
refuse. Path manifests must be tracked and contain no unbound ignored package
inputs. Git dependencies bind the enclosing repository, its exact revision and
empty Cargo marker; other resolved source packages bind every input beneath
the package, including ignored bytes. Manifest selections, all discovered
dependency closures and the complete original pair are rebound after every
outcome and again before later consumption.

Each canonical dependency root gets one initial complete source/content binding,
shared by all packages and observations. Each Git package still resolves its
actual top-level through controlled Git and must match that original root's
source kind and exact revision. Reuse never refreshes the retained identity.
Canonical manifest bindings retain every original alias/link selection and
source identity once; each complete metadata record separately maps all package
IDs to those bindings. Whole-pair/dependency checks before and after every
resolver outcome and at final handoff remain complete.

The native resolver execution/admission producer supplies separate live
authority; captured bytes and reported cleanup cannot supply it. The closed
`sealed-metadata-v1` probe purpose is unchanged and cannot run Cargo's resolver,
which can start compiler subprocesses. This consumer does not retire
`stack_feedback.py`, qualify workloads or provide proof/release authority.

The concrete native frontend now exposes `targo trust gate qualify-pair
dependencies`. It performs the original receipt/identity probes before consuming
the same owner into full locked/offline dependency comparison. The exact control
and candidate Targo execute under distinct native resolver roots; role5 queries
retain their original SDK/resource owners. Older SDK capabilities and unsupported
configuration refuse. Saved root-report bytes cannot reconstruct these owners.
The native engineering path-dependency case has actual completed query/root and
retirement evidence; complete paired production SDK/workload qualification and
all helper retirement conditions remain separate.

## Native consumer workloads

`targo trust gate qualify-pair workloads` continues the same successful probe
and dependency owner into native execution. Use the dependency stage's required
input options and add `--workload-output NEW_DIR`; `--repetitions` defaults to 3
and `--timeout` to 3600 seconds per phase. `--out` remains a new report outside
the build/evidence directory. Full command help is available with:

```text
targo trust gate qualify-pair workloads --help
```

Each side retains one actual Targo compilation graph and its original output
capsule. Intermediate build scripts run within that graph; both complete harness
inventories precede repeated native samples. Control retirement precedes candidate
admission. The consumer rechecks original inputs around every continuation and
outcome, compares complete test names, and requires actual accounted root/member
retirement and stream closure. Failed samples stay in the planned population.
Captured frames, metrics and ACKs grant no execution, proof or source authority.

The frontend writes actual binary prefixes before decoding and joins its original
interactive readers before final snapshots, including errors and cancellation.
Root CPU and separately hosted member CPU keep distinct owning-wait scopes.
Unsupported hosts/SDKs/configurations refuse without local execution fallback.
Explicit private-store root delivery is currently closed pending independently
validated original-store intake; helper pinning alone cannot select the backend.
Component controls are not matched whole-SDK/host or complete paired qualification.
AY census production, native std/nested/proc-macro support, remaining lock policy
and active-caller migration remain required before supporting helpers are deleted.
